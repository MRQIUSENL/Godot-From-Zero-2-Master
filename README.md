## 怎么打开

每个子目录都是一个**完整独立**的 Godot 项目，各自有自己的 `project.godot` 和自己的 `.gitignore`。

用 **Godot 4.7 或更高版本**（标准版，不是 .NET 版）导入对应目录下的 `project.godot`，不要从这个仓库根目录导入。

## 目录约定

```
.
├── README.md              # 本文件：所有游戏的索引
├── DEVLOG.md              # 开发日志：每天实际做了什么
├── .gitignore             # 兜底忽略规则，对所有子项目生效
└── knight/                # 一个游戏一个顶层目录
    ├── project.godot
    ├── README.md          # 这个游戏自己的说明
    └── ...
```

新增一个游戏的流程：

1. 在仓库根新建一个游戏目录，名字用小写英文，多个词之间用下划线（如 `space_shooter`）
2. 在 Godot 里进入该目录新建项目，编辑器会自动生成 `project.godot` 和 `.gitignore`
3. 在它自己的 `README.md` 里写清玩法、操作和素材来源
4. 回到本文件，在「游戏列表」表格里加一行，链接到它的目录

这样每个游戏的文档、代码、素材都完整地待在自己目录里，互不干扰。

## 开发日志

每天的实际情况记在 **[DEVLOG.md](DEVLOG.md)**，一天一条，最新写在最上面。

里面记的是真实改动、当时遇到的问题、发现但还没修的问题，以及下次开工第一件事 —— 不记「今天看了几集教程」。想看这个项目怎么一步步长出来的，看那个文件。

## 关于 `.godot/` 目录

Godot 编辑器会在项目里生成 `.godot/` 缓存目录，里面有导入后的纹理、编译产物和运行临时文件，体积很容易涨到几十兆。它是**引擎自动重建的**，不属于源码，已被 `.gitignore` 排除，请不要手动提交。

## 引擎版本

目前所有子项目统一使用 **Godot 4.7.x**（Forward Plus 渲染器，GDScript）。主分支不再保留 Godot 3 或 4.0–4.2 时代的写法。
